Installer mon atelier dans un Trial AWS

Préparez votre compte avant le 24 novembre. L’installation est rejouable le jour J ; les dix premières minutes de pratique servent à vérifier l’environnement.

  1. Ouvrez un Trial Databricks sur AWS. Express signup crée un workspace serverless sans identifiants AWS. Vérifiez crédits et date de fin : l’essai documenté dure 14 jours.
  2. Téléchargez le notebook autonome, puis utilisez Workspace → Import dans votre Trial. Choisissez Serverless.
  3. Exécutez jusqu’à « Préparer mon installation ». Renseignez les widgets : catalogue existant et inscriptible, schéma stationf_20261124_votre_equipe, SQL warehouse ID, action installer.
  4. Exécutez « Installer et vérifier », « Créer mon Genie Agent », puis « Mon reçu et mes liens ». Les trois tables et un Agent sont créés ; les ressources compatibles sont conservées à la relance.
  5. Ouvrez le lien Genie affiché. Reportez les valeurs du reçu dans « Liens de session et environnement » du portail. Posez votre première question et inspectez son SQL.

Dans le ZIP extrait, le notebook est déjà dans notebooks/00_START_HERE.ipynb : sélectionnez directement ce fichier lors de l’import, sans le télécharger de nouveau. Un navigateur qui affiche du JSON peut aussi l’enregistrer avec l’extension .ipynb.

Les 648 lignes synthétiques sont embarquées : aucun téléchargement depuis le calcul ni token à copier. Le kit réutilise votre warehouse ; il ne crée pas de compte, de catalogue ou d’App Space.

App Builder est conditionnel. Cette Beta demande une région compatible, la preview Governed agentic app-building et un App Space préparé. AWS Paris n’est pas dans la liste publiée au 17 novembre 2026. Si Builder est absent, approfondissez Genie et consignez Builder BLOCKED.

Le propriétaire du Trial est souvent administrateur : les tests de refus exigent une seconde identité limitée, sinon NOT RUN. La répétition sur un vrai Trial reste à effectuer ; les contrôles locaux du kit ne la remplacent pas.
